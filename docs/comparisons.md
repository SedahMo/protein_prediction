# 四种比较应回答不同的问题

## 1. 点突变 ΔΔG

同一参考结构、相同链组成/长度/连接拓扑，在明确 PDB 位置进行氨基酸替换。BuildModel 为每种突变生成局部处理匹配的 WT，解析其 Dif；不可减去另一个不匹配 WT 的总能量。联合突变的结果属于联合设计，不能假定等于单点之和。建议默认 5 次重复，关注重复范围，并跨合理结构检查方向一致性。当前脚本不将折叠 ΔΔG 解释为抗原亲和力变化。

## 2. linker 构型

linker 长度、柔性或组成变化可重排连接区和域间取向。即便只有替换且长度相同，如果 linker 本身无序，固定骨架 BuildModel 也只回答选定构象下的局部能量问题。需要分别建模多个构象，检查域折叠、VH/VL 界面接触/埋藏面积、连接区拉伸和碰撞、暴露疏水面及模型间一致性。不要仅按每个模型的 FoldX 总分比较设计。

## 3. VH/VL 顺序变化

VH–linker–VL 与 VL–linker–VH 改变拓扑和末端位置，不能作为常规点突变。保持相同成熟域序列和预测条件分别生成模型集合，检查域内结构与域间界面是否保留、linker 是否支持目标几何，以及聚集/错误配对风险。用表达量、SEC 单体比例、nanoDSF/DSC 与抗原结合确认工程收益。

## 4. 不同蛋白或独立结构

不同长度、Fc/VHH 组合、链组成、修复程度及预测骨架会改变能量基线。绝对总能量、每残基归一化能量均不构成通用热稳定性排序。优先比较可解释的结构质量、可开发性指标与实验终点；同源域可在明确对应关系后单独提出点替换问题。当前代码对 comparison 非 point_mutation 一律停止；这三条结构路线提供输入规范和分析方案，尚无自动结构建模实现。

## 报告模板

1. 科学问题、参考/候选构建体、比较类型。
2. 完整序列、域边界、linker、结构来源/置信度、编号映射。
3. 软件版本、条件、输入校验和、修复记录、重复数量。
4. 点突变逐运行结果、均值/SD/范围；按模型分别展示。
5. 结论适用范围、跨模型方向一致性、待实验确认的问题。
6. 下一步：表达/SEC/热转变/应力稳定性，必要时加功能 assay。
